# Suggested inter-controller wiring

ESP32 GPIO16 (RX2)  <- Nano TX (D1)
ESP32 GPIO17 (TX2)  -> Nano RX (D0)
GND                 --- GND

ESP32:
SD_CS = GPIO5
CAN_CS = GPIO15
CAN_INT = GPIO4
Nano UART = GPIO16/17
K-Line UART (L9637D) = GPIO25 (RX) / GPIO26 (TX)
DUT voltage ADC = GPIO34
DUT current ADC = GPIO35
Supply voltage ADC = GPIO32

NOTE ON CAN_INT:
CAN_INT (GPIO4) is wired but not yet used by firmware — the current
MCP2515 driver (ESP32_Firmware/can_mcp2515.ino) polls CANINTF over SPI
instead of using the interrupt line. Wire it anyway for a future
interrupt-driven revision.

NOTE ON K-LINE:
ESP32_Firmware/kline_iso14230.ino implements ISO 14230 fast-init and basic
request/response framing over this UART. It has not been validated
against a real K-Line ECU — bench-test with a scope before trusting it
against a vehicle module.

Nano:
D4  = DUT relay driver (relay 1)
D5  = Auxiliary relay 2 driver
D7  = Auxiliary relay 3 driver
D8  = Auxiliary relay 4 driver
D3  = Emergency stop input (INPUT_PULLUP)
D6  = Buzzer
D13 = Status LED
A0  = DUT voltage
A1  = Supply voltage
A2  = Current sensor
A3  = Temperature (read as an LM35: 10 mV/degC; change TEMP_C_PER_V for other sensors)

Optional feedback for aux relays 2-4 (Nano D2, D11, D12): wire a signal that
follows each relay (an auxiliary contact, or an optocoupler across the load)
to these pins, then set AUX_FEEDBACK_ENABLED to 1 in the Nano sketch (inputs
use INPUT_PULLUP; AUX_FB_ACTIVE_LOW selects the sense polarity). With it on,
RELAY_TEST for relays 2-4 reports real PASS/FAIL; with it off (default) it can
only report ACTUATED because nothing observes those relays.

Over-temperature trip: A3 is read as an LM35 (10 mV/degC). The trip is off by
default and is enabled from the app (Controls > Protection) or with
SET_TEMP_LIMIT. Only enable it after wiring a real sensor to A3 - an unconnected
input gives meaningless readings and could trip (or fail to trip) wrongly.

Relays 1-4 share the one polarity setting (SET_RELAY_POLARITY) and are all
driven OFF at boot, on e-stop, on any fault, on heartbeat loss and on
POWER_OFF. Drive relay coils through the module's own driver/opto stage - do
not power coils from the Nano pins.

Extra ESP32 pins for the live-data preview:
GPIO21 = I2C SDA, GPIO22 = I2C SCL  -> optional INA219 (addr 0x40, 0.1 ohm
         shunt, readable to ~3.2 A with the default range)
GPIO33 = position feedback (0-3.3 V -> 0-100 %; protect/divide the real
         sensor signal. Internal pull-down: unconnected reads 0 %, which is
         not a real position)

NOTE ON RELAY POLARITY:
The relay module's electrical logic must match the firmware. The default is
now ACTIVE-LOW (GPIO LOW = energized, HIGH = off) for all four relays; before
this change it was active-high. A Nano that has already saved a polarity to
EEPROM keeps that value, so only a fresh/reset unit changes behaviour. It is
runtime-configurable instead of requiring a firmware edit: use the app's
Controls > Relay Polarity, or send `SET_RELAY_POLARITY,0` (active-high) or
`SET_RELAY_POLARITY,1` (active-low) to the Nano over UART; it persists to
EEPROM. The Nano forces the relay off
before and after changing this setting. You must still confirm which
value is correct against your actual relay module on the bench — nothing
here has verified your physical wiring for you.

NOTE ON ADC CALIBRATION:
SUPPLY_DIVIDER, DUT_DIVIDER, CURRENT_ZERO_V, and CURRENT_V_PER_A in the
Nano firmware are uncalibrated placeholders. Use these UART commands
against a trusted reference meter to calibrate and persist real values to
EEPROM (see Arduino_Nano_Safety/TIFF_TESTER_PRO_SD_NANO.ino header
comment for full command list):
  CAL_SUPPLY,<actual_voltage>            (measure supply with a multimeter)
  CAL_DUT,<actual_voltage>               (measure DUT rail with a multimeter)
  CAL_CURRENT_ZERO                       (DUT off, captures the sensor's zero point)
  CAL_CURRENT_SCALE,<actual_current_a>   (known load, measure with a trusted ammeter)
  GET_CONFIG                             (reads back current calibration state)
  RESET_CALIBRATION                      (reverts to firmware-default placeholders)
No calibration has actually been performed against real hardware here —
this only provides the mechanism; you still need to do it on your bench.

Do not connect automotive 12 V signals directly to ESP32/Nano GPIO pins.
Use suitable dividers, protection and/or isolation.
